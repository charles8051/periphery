Periphery · ADR-0061 · firmware-flashing platform

One Seam, Many Paths

A firmware flasher is one sentence: discover the target, speak its bootloader's protocol over the right transport, write, verify, leave. The whole platform is the disciplined refusal to let that sentence fragment. A single seam faces the application; behind it, three orthogonal axes — transport, MCU family, and file format — vary independently, and a pure functional core keeps every path byte-exact and testable with no hardware.

01 The seam everything speaks to

Three methods. One registry. Nothing above it knows what a DFU block is.

The application — the FlashAnything service, its CLI and Avalonia GUI, and (soon) hands-free autoflash — never mentions STM32, USB, or Intel HEX. It holds a FirmwareImage and talks to one interface:

interface IFirmwareProgrammer {
  DeviceIdentity IdentifyAsync(ct);
  FlashResult   FlashAsync(FirmwareImage img, FlashOptions opts, IProgress<FlashProgress> p, ct);
  void           LeaveAsync(ct);
}

A BootloaderRegistry turns a discovered DeviceInfo into the right implementation: each IBootloaderProvider answers CanHandle(device), and the first match OpenAsyncs the programmer. That is the entire coupling between "what got plugged in" and "which protocol stack runs."

02 One seam, three orthogonal axes

The seam doesn't split once. It splits along three axes that never entangle.

Behind IFirmwareProgrammer, three questions vary independently. How do bytes physically move? Whose bootloader protocol are we speaking? And what on-disk format did the firmware arrive in? Each axis is ignorant of the other two — a transport doesn't know the MCU family, a file format doesn't know the transport — which is exactly why the combinations multiply without the code multiplying.

The honest-naming rule. Only the USB targets are literally DFU (the USB Device Firmware Upgrade class, AN3156). Calling the serial packages *.Dfu.* would re-create the very AN3155-vs-AN3156 confusion the platform exists to kill — so the umbrella is Periphery.Bootloader, and "Dfu" is reserved for the one place it's true.

03 How the axes become packages

Periphery.Bootloader.{family}.{transport} — and the family level holds shared code iff the family has any.

Each leaf is one (family, transport) client riding a Periphery transport spoke and consuming two shared foundations: Periphery.Firmware (the image model) and the Periphery.Bootloader contract. The family node in between is load-bearing only when a family shares a protocol across transports:

  • Different protocol per transport → no family core. STM32's USB (DFU) and Serial (AN3155) share no wire protocol, so the transports are independent.
  • One protocol, many transports → a real family core. EFM8's AN945 boot-record protocol is identical over HID / UART / SMBus — only framing differs — so Periphery.Bootloader.Efm8 holds it and the transports are thin.

04 Orthogonality, made concrete

Families are rows; transports are columns; the shared plane spans every cell.

Because the axes are independent, the package set is a sparse matrix. Adding ESP32 is a new row; giving EFM8 a serial transport is a new cell — neither perturbs anything else. And every cell, present or future, rests on the same plane: one image model and one contract.

05 Inside one cell: pure core, thin seam, imperative shell

The same discipline, one level down — values and a planner stay pure; IO, the clock, and the poll loop live in the shell (ADR-0052).

Take Stm32.Usb. Its pure core is values and total functions: a FirmwareImage plus FlashOptions go into Stm32DfuPlan.Plan(...), which returns an ordered, immutable list of DfuSteps — a closed union of MassErase, SetAddress, WriteBlock, Leave. No Task, no socket, no clock. It is byte-exact and unit-tested with zero hardware.

Between the plan and the wire sits a tiny transport seam, IStm32DfuTransport (Download / GetStatus / ClearStatus / …), so the shell can run against a scripted fake. The imperative shell, Stm32DfuProgrammer, owns the messy edges: the USB handle, and the protocol's defining behaviour — a DNLOAD does nothing until GETSTATUS, which returns a device-dictated bwPollTimeout the shell must wait out.

06 The same trick again: file formats

Two kinds, one universal detector. Memory images collapse to a single value; packaged blobs stay with the family that speaks their protocol.

The format axis is its own little abstraction exercise. Every firmware file is one of two kinds, and that split decides what can be shared. Memory images — Intel HEX, raw bin, S-record, ELF, DfuSe — all coalesce to the same value, FirmwareImage (contiguous addressed segments), which any byte-writing flasher consumes without caring which format produced it. Packaged blobs — EFM8 boot-records, Gecko GBL, a Nordic .zip — carry their own signatures and structure and are the bootloader's native input; they are validated and unwrapped, never flattened to segments.

Spanning both kinds is one universal detection / brick-sniff registry: every format registers its extensions and a content magic-byte test, and a single Detect() reconciles the two — refusing, for instance, a .hex mislabelled as .bin before a single text byte reaches flash.

07 Why it reads as beautiful

Four properties fall out of the same decision: keep the seam narrow and let the variation live behind it.

Orthogonality

Transport, family, and format vary independently. The combinatorial surface (5 families × 4 transports × N formats) never becomes combinatorial code — each axis is one ignorant-of-the-others layer.

Purity

Every protocol decision is a value transform — Plan, Encode, Decode — so the dangerous bytes are byte-exact and unit-tested with no MCU on the bench. Only timing and IO are impure, and they sit in one obvious place.

Honesty

Names refuse to lie. "DFU" appears only on the USB-DFU path; the umbrella is Bootloader. The taxonomy itself prevents the AN3155-vs-AN3156 category error that motivated the whole platform.

Graduation

Abstractions are earned, not invented. The generic DFU layer stays an internal seam until a second USB-DFU target appears; the contract graduates once two clients prove its shape. Nothing is general before it has two reasons to be.

The whole thing in one line: a DeviceInfo selects a protocol over a transport that writes a FirmwareImage — and every word in that sentence is a seam you can vary without touching the others.
